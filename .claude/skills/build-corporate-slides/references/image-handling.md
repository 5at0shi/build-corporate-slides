# Image Handling

`input_dir` 配下の画像、図表、参考資料は、ユーザーの使用指示に従って扱う。

- スライド番号の指定があれば優先する。
- 「システム構成を説明するページ」のような内容ベースの指定はSlide Planとの対応を判断する。
- 写真、ロゴ、複雑な図表は原則として画像のまま使う。
- 簡単な図をPowerPoint図形として再構成するのは、明示指示がある場合、または編集性が重要で内容を変えず再現できる場合に限る。
- アスペクト比を維持し、必要ならcropする。情報を欠落させるcropはしない。
- 図表内文字が読めないほど縮小しない。必要なら専用ページ、拡大抜粋、または複数ページを提案する。
- 出典、権利、ロゴの余白規定を尊重する。不明なら確認事項として示す。
- 内容上の必然性がない背景装飾として画像を流用しない。

## ロゴ

- ロゴの有無は `.slide-skill-config.yaml` の `branding.logo.enabled` に従い、AIが任意に省略しない。
- 背景透過PNGを優先する。白背景が残る場合は、権利と形状を変えず背景だけを除去する。
- アスペクト比を維持し、幅0.35〜0.6インチ程度を基準に小さく使う。
- ブランド面または余白の隅へ置き、タイトル、開示範囲、部署名、日付より目立たせない。
- `enabled: true` の場合、解決順は (1) `branding.logo.path` に明示指定された画像 (2) `input_dir` 直下の `company-logo.png`（configを編集せず、この決まった名前・場所に置くだけで自動的に使われる。差し替える際も同じファイル名へ上書きするだけでよい） (3) Skill同梱の `assets/logo-placeholder.png`。
- `enabled: true` なのに解決先が存在しない場合は警告または生成停止とし、黙ってロゴなしにしない。

## PNGグラフ

グラフがPNGで渡された場合も、ネイティブchartへの作り直しを前提にしない。

- 数値、凡例、軸、注記を改変せず画像として配置する。
- 余白が大きい場合は、情報を欠落させない範囲でcropする。
- 複数PNGは、画像内の文字サイズが揃って見えるよう表示寸法を調整する。
- 元画像の解像度が不足する場合は、過度な拡大を避け、専用ページや画像差し替えを提案する。
- 配色の調整は、ユーザーの意図が明確で、系列の意味を変えない場合だけ行う。
- 結論を強く示す場合は結論主導型、データ全体を公平に見せる場合は標準型を選ぶ。該当時は [layout-patterns.md](examples/layout-patterns.md) を読む。

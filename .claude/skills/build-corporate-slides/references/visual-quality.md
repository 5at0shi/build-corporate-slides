# Visual Quality

## Design Objective

モダンでスマートな企業資料を作る。角丸、カード、淡色面、グラデーション、影、アクセント色は必要に応じて使用してよい。表現を機械的に禁止せず、情報の階層、グルーピング、重点、状態、ブランド性を明確にするために選ぶ。

「AIらしさを消す」ことを目的にしない。同じ表現の反復、意味のない装飾、主役の競合、情報構造と見た目の不一致による違和感を防ぐ。

## Positive Design Language

- **Dense but breathable**: 十分な情報量を、揃った余白とグルーピングで読みやすくする。
- **Typography carries hierarchy**: サイズ、ウェイト、色、行間を階層の第一手段とする。
- **Modern with controlled depth**: 淡色面、角丸、軽い影で奥行きを作れるが、強度を揃えて使う。
- **Visual elements earn their place**: 視覚要素は、構造、関係、強調、視線誘導、状態、ブランドのいずれかへ寄与させる。
- **One visual priority**: ページ内で最も強い要素を原則一つにする。
- **Editorial variation**: 同じCardや同じ「横並び＋下部結論」を反復せず、内容に応じて重心と読順を変える。

## Visual Layers

- `Base`: 白・オフホワイト・薄いグレー・本文・細線。通常情報。
- `Structure`: 淡色背景エリア・角丸・区切り・軽い影・青の濃淡。まとまりや構造。
- `Focus`: 濃紺・鮮明なブルー・限定的なアクセント・サイズ差。結論や重要項目。

各ページに3層すべてを置く必要はない。強調対象が一つならFocusを集中させ、同種の並列要素には青の濃淡、異種の構造にはラベルと限定的な色相差を使う。色だけで意味を伝えない。

## Layout and Lines

- 安全余白、タイトル位置、カラム境界、ベースラインをデッキ内で揃える。
- スライドタイトル下はシャープなブランドブルーの線を標準とする。
- セクション見出しは短い縦線とテキストを組み合わせ、階層を明確にする。
- 表や補助線はニュートラルグレー、主要な接続や選択状態はブルーを使う。
- 線に常時影を付けない。影は線をぼかすためではなく、面を背景から分離するために使う。
- 背景エリアの端をカラム、余白、他要素の基準線へ揃える。
- 線は構造を補助するために使い、線だけで関係を説明しない。縦線と横線が増えたら、背景領域、位置、余白への置き換えを検討する。
- タイムラインでは、フェーズとゲートを同じ行へ混在させない。ゲート位置は工程上の時点と揃える。
- 項目数が少ない見出し＋リストを領域内で上下中央に置く場合、項目同士の間隔は最小値（詰めた自然な間隔）のまま中央寄せしない。周囲の余白だけが広がり、項目群が窮屈に固まって見える。項目間の間隔も合わせて広げてから中央寄せ位置を計算する（`slidekit.textmetrics.estimate_*_height_pt`系のbody_gapを広げる）。ただし広げすぎて周囲の余白とほぼ同じ間隔になると、今度は項目群としてのまとまりが失われ、バラついた印象になる。項目間の間隔は周囲の余白よりも明確に狭く保つ（目安として余白:項目間隔が概ね1.3〜1.5:1程度。項目のまとまり感を保ちつつ窮屈さを避ける範囲）。数値は内容量・段組幅で変わるため、レンダリングして確認しながら調整する。

## Shapes and Depth

- 角丸はモダンな表現として使用できる。小〜中程度を標準とし、ページ内で半径を揃える。
- Cardには境界線または軽い影を使える。Background Zoneには原則として強い境界や影を付けない。
- すべてをCardへ入れない。表、チャート、フローは必要なまとまりだけ背景面で支える。
- グラデーションは表紙やブランド面、連続量の表現など意味がある場合に限定する。
- 表紙のブランド面は左右どちらにも置ける。直線・斜め・滑らかな曲線を選べるが、単純な大きい輪郭を一つ使い、装飾線や小形状を重ねすぎない。

## Key Message

Key Messageは意味上のComponentであり、濃紺帯に固定しない。

- `editorial`: 結論文＋短いブランド線。
- `subtle`: 淡色面や左線による控えめな結論。
- `solid`: 強い結論を示す限定的な濃色面。
- `card`: 周辺要素から独立した要約。
- `plain`: 装飾なし。ページタイトル直下の罫線に短い線を重ねたくない場合（ページ冒頭の導入文など）に使う。

ラベルがなくても結論と分かる場合は、`KEY MESSAGE`、`KEY TAKEAWAY`、`PRINCIPLE`などの制作ラベルを置かない。必要な場合は「結論」「導入条件」など、読み手に意味のある日本語を控えめに使う。

## Tables

- 罫線はニュートラルグレーを使い、黒い外枠を強く見せない。
- 最重要の行だけ淡色背景を使う。次点の列は文字色・太さで示す。
- 行と列の背景色を交差させない。
- 下部に結論を置く場合は、通常は淡色面、強い判断だけ濃紺面を使う。
- Excelの見た目をそのまま再現せず、行間、列幅、文字揃えをPowerPoint向けに調整する。

## Relationship and Organization

- 実行時の横の役割分担と、意思決定の縦の階層を分けて考える。
- 両方が必要なら、上段に意思決定、中段に運営、下段に部門別実行を置く。
- ハブ型は連絡経路や集約先を示す場合だけ使う。責任階層を説明する用途へ無理に使わない。
- 接続線は必要最小限にし、線がなくても背景領域と位置から構造が読めることを目指す。

## Readability and Accessibility

- 通常テキストは背景との十分なコントラストを確保する。淡色面には対応する濃色文字tokenを使う。
- 色による分類にはラベル、位置、形状、線種のいずれかを併用する。
- 標準の `business` は本文12pt、注記10ptを基準にする。
- `dense` でも本文11.5pt未満を常態化させない。縮小前に重複削除、段落統合、表化、ページ分割を検討する。
- `large-room` は遠距離投影が明示された場合だけ使う。
- 重要な文字を画像だけに含めない。可能な限りPowerPointテキストとして保持する。
- オブジェクトの追加順を、自然な読順に近づける。

## Visual QA

レンダリングした各ページを確認する。

- ページ内で最も強い要素が複数競合していないか
- 色を消しても、ラベル・位置・形状から構造が理解できるか
- アクセント色、背景面、Card、影の役割を説明できるか
- Background ZoneとCardを混同していないか
- 同じCard構成が3ページ以上連続していないか
- タイトル下線とセクションマーカーが、同じ階層で一貫しているか
- 背景色と文字色の組み合わせに十分な可読性があるか
- 影の方向・強度、角丸の半径がページ内で揃っているか
- 投影／手元閲覧モードに対して文字サイズが適切か
- 行切れ、はみ出し、重なり、読めない縮小がないか
- PowerPointで人間が編集しやすいか
- 同じ見出し配下の箇条書きが一項目ずつ別textboxになっていないか
- 番号、見出し、説明が無理由に別shapeへ分解されていないか
- 100%表示と画面共有相当の縮小表示の双方で、階層と本文が読めるか

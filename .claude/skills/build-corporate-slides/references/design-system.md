# Design System

## Decision Rules

| 状況 | 第一候補 | 避ける判断 |
|---|---|---|
| 一つを強調 | 濃い青、サイズ差、余白を一か所へ集中 | 複数の濃色面を競合させる |
| 同種の並列項目 | 青の濃淡、同じ形、共通軸 | 項目ごとに無関係な色を付ける |
| 異種の複数構造 | 青＋青緑＋限定的アクセント、ラベル併用 | 色だけで分類する |
| 緩やかなまとまり | `Background Zone` | 大きな影付きCardで囲う |
| 独立して比較・操作する単位 | `Card` | すべての文章をCard化する |
| ページの結論 | `Key Message` | 常に濃紺帯にする |
| 重点対象 | `Focus Panel` | 背景面と同じ強度にする |

## Semantic Color Roles

- `text_primary`: 見出し・本文の主文字
- `text_secondary`: 注記・補足
- `line_neutral`: 表・区切り・非強調の接続
- `line_brand`: タイトル下線・セクションマーカー・主要接続
- `surface_base`: 通常背景
- `surface_subtle`: ニュートラルな補助面
- `surface_brand_soft`: 青系のまとまり・選択範囲
- `surface_teal_soft`: 異なる構造の補助系列
- `focus_primary`: 最重要項目
- `accent_secondary`: 複数構造を区別する限定的アクセント

淡色面は文字色とセットで使う。`surface_brand_soft` 上では `text_primary`、濃色の `focus_primary` 上では白を使用する。

## Emphasis Order

強調対象が複数ある場合は、同じ強度を重ねない。

1. 結論を左右する最重要情報だけ、淡色背景または濃色面を使う。
2. 次に見てほしい情報は、文字色、太さ、サイズで示す。
3. 補助情報は位置、余白、ニュートラルグレーの線で整理する。

行と列の背景色を交差させない。表では最重要の行だけ背景色を使い、判定列など二次的な注目対象は文字色と太さを優先する。複数の濃色面を競合させない。

## Conclusion Strength

- 通常のまとめ: `subtle`。淡い青または薄いグレーの面に濃紺文字。
- 強い判断: `solid`。濃紺面に白文字。1文に絞り、ラベルや区切りを増やさない。
- 本文中の短い主張: `editorial`。短いブランド線と太字。

濃紺の結論ボックスは、ページの判断を必ず伝える必要がある場合だけ使う。デッキ内で反復しすぎない。

## Component Boundaries

| Component | 役割 | 境界・影 |
|---|---|---|
| Background Zone | 範囲、まとまり、フェーズ | 原則なし。影なし |
| Card | 独立した情報単位 | 細線または軽い影 |
| Focus Panel | ページ内の重点対象 | 色・線・サイズで明確化 |
| Key Message | ページの結論 | 内容に応じ4スタイル |
| Section Lead | セクション内の見出し | 短いブランド線＋文字 |
| Cover Brand Field | 表紙のブランド面 | 情報を詰め込まない |

## Common Structural Choices

- 課題と対応策: 左に課題、右に淡い背景の対応領域。優先度は狭い補助列で示す。
- 組織: 縦に責任階層、横に実行部門を配置できる。線より背景領域と位置を優先する。
- プロセス: フェーズ、作業、判断ゲートを別レイヤーにする。ゲートはタイミングが分かる専用軸へ置く。
- 表: 薄いグレーの罫線、十分な行間、背景色は例外行だけ。縦線は必要最小限。
- 複数グラフ: 標準型と結論主導型を、強調したいメッセージの強さで選ぶ。

## Typography Modes

標準見出しはモダンなゴシック系とする。明朝体はeditorialな表現が内容に合う場合だけ選ぶ。

- `business`（標準）: title 26〜28pt、section 18〜22pt、body 12.5〜15pt、note 9〜11pt
- `dense`: title 24〜27pt、section 15〜18pt、body 11.5〜13.5pt、note 8.5〜10pt
- `large-room`: title 30〜34pt、section 18〜22pt、body 16〜18pt、note 11〜13pt

文字サイズは情報を収める最後の調整手段とする。先に重複を削り、意味単位をまとめ、背景領域と余白で構造化する。生成コードで個別サイズを乱立させず、modeのtokenを基準にする。

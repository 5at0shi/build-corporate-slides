# Design System

## Decision Rules

| 状況 | 第一候補 | 避ける判断 |
|---|---|---|
| 一つを強調 | 濃い青、サイズ差、余白を一か所へ集中 | 複数の濃色面を競合させる |
| 同種の並列項目 | 青の濃淡、同じ形、共通軸 | 項目ごとに無関係な色を付ける |
| 異種の複数構造 | 青＋青緑＋限定的アクセント、ラベル併用 | 色だけで分類する |
| 緩やかなまとまり（アイコン付き統計チップの並び等） | `Background Zone`（`add_panel`） | 裸の背景に浮かせる |
| 独立して比較・操作する単位（並列するカテゴリ・アイコン付きリストの列等） | `Card` | すべての文章をCard化する／裸の背景に浮かせる |
| ページの結論 | `Key Message` | 常に濃紺帯にする |
| 重点対象 | `Focus Panel` | 背景面と同じ強度にする |

## Semantic Color Roles

- `text_primary`: 見出し・本文の主文字
- `text_secondary`: 注記・補足
- `line_neutral`: 表・区切り・非強調の接続
- `line_brand`: タイトル下線・セクションマーカー・主要接続
- `surface_base`: 通常背景
- `surface_subtle`: ニュートラルな補助面
- `surface_brand_soft`: 青系のまとまり・選択範囲
- `surface_teal_soft`: 異なる構造の補助系列
- `focus_primary`: 最重要項目
- `accent_secondary`: 複数構造を区別する限定的アクセント
- `positive`/`negative`/`warning`: 符号・重大度専用（詳細は次項）

淡色面は文字色とセットで使う。`surface_brand_soft` 上では `text_primary`、濃色の `focus_primary` 上では白を使用する。

### 符号・重大度の色（positive / negative / warning）

- `positive`: 良い結果・改善（緑）
- `negative`: 悪い結果・リスク（赤）
- `warning`: 注意・要確認（オレンジ系）

これらはブランドカラーとは独立に固定する。読み手は「赤＝悪化」を慣習として読むため、ブランド色を変えても意味がズレてはならない。装飾用の汎用アクセント（単に色数を増やしたい、目を引きたい）としては使わない。数値の符号（文字列が"-"で始まるか）で自動判定しない。削減率のように、マイナスの数値が良い結果を意味することがあるため、内容の意味を判断できる側（contentを書く側）が`tone`として明示する（`stat_highlight`の`stat.tone`/`supporting[].tone`が現在の実装箇所）。

淡色版（`surface_positive_soft`/`surface_negative_soft`/`surface_warning_soft`）もあり、`add_background_zone(tone="positive-soft"/"negative-soft"/"warning-soft")`でBox/Zoneの背景として使える（`BoxGrid`等のFragmentへ`tones`として渡す場合も同様）。特定のrendererに紐づく機能ではなく汎用のComponent部品（`add_background_zone`）のため、リスクや悪化を示すセル・ゾーンが必要な場面であれば、どのrendererからでも使ってよい。

### ブランドカラーのカスタマイズについて

現状、`PALETTE`は`theme.py`に固定された値で、config経由の上書きはできない（`typography`は`config.typography`で上書きできるが、色には対応する仕組みがまだない）。これは意図的な先送りであり、「今のところ複数ブランドでの利用実績がなく、需要が無いまま自動配色の仕組みを作ると過剰設計になる」という判断による。

将来、実際に別ブランドカラーでの利用需要が出た場合の実装方針は以下を推奨する。

- **機械的に導出してよい部分**: ブランド色1つ（hex）を起点に、LCH/OKLCH等の知覚均等な色空間で明度を段階的に振り、WCAGコントラスト比（本文4.5:1等）を満たす階調（`line_brand`、`surface_brand_soft`等）を算出する。これは確立された手法で、自動化してよい。
- **機械的に決めるべきでない部分**: `accent_secondary`のような「ブランドとは別の系列を区別する色」は、ブランドの世界観に関わる判断のため、自動選定はしない。configで明示指定できるようにし、未指定時は現状のteal等、実績あるフォールバックを使う。
- `positive`/`negative`/`warning`はブランドカラーに連動させない（上記の理由）。

## Emphasis Order

強調対象が複数ある場合は、同じ強度を重ねない。

1. 結論を左右する最重要情報だけ、淡色背景または濃色面を使う。
2. 次に見てほしい情報は、文字色、太さ、サイズで示す。
3. 補助情報は位置、余白、ニュートラルグレーの線で整理する。

行と列の背景色を交差させない。表では最重要の行だけ背景色を使い、判定列など二次的な注目対象は文字色と太さを優先する。複数の濃色面を競合させない。

## Conclusion Strength

- 通常のまとめ: `subtle`。淡い青または薄いグレーの面に濃紺文字。
- 強い判断: `solid`。濃紺面に白文字。1文に絞り、ラベルや区切りを増やさない。
- 本文中の短い主張: `editorial`。短いブランド線と太字。

濃紺の結論ボックスは、ページの判断を必ず伝える必要がある場合だけ使う。デッキ内で反復しすぎない。

## Component Boundaries

| Component | 役割 | 境界・影 |
|---|---|---|
| Background Zone | 範囲、まとまり、フェーズ | 原則なし。影なし |
| Card | 独立した情報単位 | 細線または軽い影 |
| Focus Panel | ページ内の重点対象 | 色・線・サイズで明確化 |
| Key Message | ページの結論 | 内容に応じ5スタイル（下記） |
| Section Lead | セクション内の見出し | 短いブランド線＋文字 |
| Cover Brand Field | 表紙のブランド面 | 情報を詰め込まない |
| Tag | ステータス・分類の小さなラベル | 常に丸薬型。枠線のみ／単色塗りの2種 |
| Stat | 数値を主役にする表現の最小単位 | 面（Card/Zone）は別途組み合わせる |

`add_background_zone(tone=...)` と、Fragmentへ `tones=[...]` として渡す面の色は次の6種。並列する複数のZoneを区別する場合は `neutral` / `brand-soft` / `teal-soft` を使い、符号・重大度を示す場合だけ後半3種を使う。

| tone | 用途 |
|---|---|
| `neutral` | ニュートラルな補助面（既定的な選択） |
| `brand-soft` | 青系のまとまり・選択範囲 |
| `teal-soft` | 異なる構造の補助系列 |
| `positive-soft` / `negative-soft` / `warning-soft` | 良い/悪い/注意の意味を持つ面（下記「符号・重大度の色」） |

`add_key_message(style=...)` は次の5種。

| style | 見た目 | 使いどころ |
|---|---|---|
| `editorial` | 左に短い青線＋太字 | 通常のページ結論（多くのrendererの既定） |
| `subtle` | 淡いグレーの面 | 表・グラフの下に添える控えめな結論 |
| `solid` | 濃紺の面に白文字 | 最も強く言い切るとき。1デッキで多用しない |
| `card` | 枠線付きの面 | 周囲にもCardが並ぶページで揃えるとき |
| `plain` | 装飾なし | ページタイトル直下の導入文など、罫線を重ねたくない位置 |

## Common Structural Choices

- 課題と対応策: 左に課題、右に淡い背景の対応領域。優先度は狭い補助列で示す。
- 組織: 縦に責任階層、横に実行部門を配置できる。線より背景領域と位置を優先する。
- プロセス: フェーズ、作業、判断ゲートを別レイヤーにする。ゲートはタイミングが分かる専用軸へ置く。
- 表: 薄いグレーの罫線、十分な行間、背景色は例外行だけ。縦線は必要最小限。
- 複数グラフ: 標準型と結論主導型を、強調したいメッセージの強さで選ぶ。

## Icons

外部アセット（アイコンフォント・SVGセット）は使わず、`slidekit.icons.add_icon`によるベクター描画のみを使う。ライセンス上の懸念を避けるためと、パレットの色をそのまま icon の色に使えるようにするため。

- 候補: `check`（完了・成功）、`warning`（リスク・注意）、`people`（体制・関係者）、`document`（資料・報告）、`clock`（所要時間・期限）、`target`（目標・KPI）、`growth`（成長・改善トレンド）、`cost`（コスト・予算）、`calendar`（日程・スケジュール。`clock`は所要時間、`calendar`は日付・締切で使い分ける）、`idea`（着想・提案・イノベーション）、`location`（拠点・エリア・店舗）、`building`（組織・会社・部門）、`globe`（グローバル・海外展開）、`shield`（セキュリティ・リスク管理・コンプライアンス）。
- すべて「semantic paletteの色チップ＋白い図形」という同じ言語で統一されている。個別に色や余白を作り込まない。
- 装飾ではなく、状態・分類を一目で区別させたい場合だけ使う。すべての箇条書きに機械的に付けない（「Visual elements earn their place」に従う）。
- 目安サイズは0.3〜0.5インチ。本文の文字サイズと同程度〜やや大きい範囲に収める。
- 箇条書きにアイコンを1行ずつ添える場合は`add_icon_list`を使う。アイコン（図形）は行ごとに独立させてよいが、文章は`add_item_list`と同様に一つのtextboxへまとめる。1文ごとに別textboxへ分割すると、PowerPoint上での編集性が著しく下がる。アイコンが不要な内容には通常の`add_item_list`を使う。`icon_size`を指定しなければ本文フォントサイズの約2倍を自動計算するため、dense/large-roomなどmodeが変わってもアイコンと文字の相対的な大きさが崩れない（固定インチ値で指定すると崩れる場合があるので、揃えたい理由がない限り既定値に任せる）。
- アイコン付きの統計チップ（数値＋ラベルを横に並べる等）や、アイコン付きリストを複数列並べる構成は、他のコンテンツと同じくDecision Rulesに従う。裸の白背景に浮かせず、緩いまとまりは`add_panel`、独立して並列するカテゴリ・列は`add_card`で囲む。アイコンだから特別扱いする理由はない。

## Typography Modes

標準見出しはモダンなゴシック系とする。明朝体はeditorialな表現が内容に合う場合だけ選ぶ。

**本文（body）は基本12pt。** 注釈・キャプション（small/note）や、情報密度が高く構造化を尽くしてもなお収まらない場合だけ、それより小さくしてよい。この基準を先に満たしたうえで、title/section/metricは比率を保って設計してある（個別に大きくしない）。

- `business`（標準）: title 22pt、section 15pt、body 12pt、note 10pt
- `dense`: title 20pt、section 15pt、body 11.5pt、note 9pt（bodyは11.5pt未満を常態化させない）
- `large-room`: title 32pt、section 20pt、body 17pt、note 12pt（この12pt基準の対象外。大会議室など遠距離投影が明示された場合だけ使う）

表紙（`add_cover`）と章扉（`add_section_divider`）の大見出しは、この本文基準スケールに連動させず、固定34ptを使う。ポスター的な一枚見出しであり、本文の読みやすさを基準にする通常ページの`title`階層とは役割が異なるため。

文字サイズは情報を収める最後の調整手段とする。先に重複を削り、意味単位をまとめ、背景領域と余白で構造化する。生成コードで個別サイズを乱立させず、modeのtokenを基準にする。
